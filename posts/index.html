嵌入式触摸屏适配全链路排障复盘：从设备树到 Qt 输入层

一、背景与目标

在一块野火 NPi-nyika（i.MX6ULL，Debian 系统，内核 4.19.35-imx6）开发板上，需要让一块 5 寸 GT9157 电容触摸屏正常工作。目标不仅是驱动层跑通，还要让板子上预装的 Qt 应用能够响应触摸。

整个排障过程跨越了设备树（Device Tree）→ 内核驱动 → 用户态输入框架（evdev/tslib）→ Qt 应用层四个层次，几乎覆盖了嵌入式 HMI 开发中最典型的所有坑。本文按时间线复盘，逐层拆解每个报错的根因与解法。

二、问题演进全景

阶段现象根因层关键结论
1new_device 手动创建设备报 request IRQ failed: -22设备树手动创建的设备没有 DT 节点，驱动拿不到 irq-gpios
2dtc 报 syntax error（宏行）设备树用了 GPIO_ACTIVE_LOW 等宏但没包含头文件
3dtc 报 #include syntax error工具链dtc 不处理 C 预处理器语法，需先 cpp
4编译成功但满屏 Warning (reg_format)设备树overlay 的已知误报，可忽略
5dmesg 出现 ID 1158 + input/input2驱动驱动跑通，中断注册成功
6触摸能用了，但 Qt 程序不响应Qt 应用层驱动通 ≠ Qt 能读，两套独立机制
7环境变量设了仍无效进程环境脚本有独立环境，终端 export 对其无效
8改 run.sh 后定位真正根因厂商脚本变量 typo + tslib/evdev 混用
